What it is

A writing tool that happens to publish a website

The site itself is static. IHG writes content files into the repository; on the live site every save is a commit on the deployed branch, so publishing is deploying and a page appears in about two minutes.

  • Nothing links to it. It is noindex, robots.txt disallows it, and every request needs the password. It is not a product anyone but the two of them will ever see.
  • The audience is not technical. The screen says "Kje na spletni strani", not "collection". It says "Osnutek vidite samo vi", not "status: draft". Any word that only makes sense to an engineer is a bug.
  • The point. A person writes a page the way they will read it, and the machine-facing parts, the URL, the meta description, the structured data, where it shows up on the site, sit beside it without taking over.

Layout

One screen, four regions

There is no separate list page and edit page. The list, the document and its settings are all present at once on a wide screen, and become overlays as the screen narrows.

Rail 64px, dark, always there. Drawer 280px, the list of everything. Work the view itself. Panel 360px, only on the editor route.

Breakpoints are 900px and 1200px. Below 900 the rail is a bottom bar with six items.

The editor

Three cards, one panel, three ways to format

The middle column is a form in three cards, not a canvas. It reads top to bottom in the order a person thinks.

  1. Naslov, povzetek, kategorija, datum. The summary carries a 0 / 220 counter. The category select ends with "+ Nova kategorija …".
  2. Besedilo. A hint line, the fixed toolbar, the editable area, then a row of block buttons: Odstavek, Naslov, Citat, Seznam, Koraki, Slika, Poudarek, Gumb, Stolpca, Tabela, Ločilo, Koda.
  3. Slika. The main picture, dropped or chosen, then its description and caption.

Formatting exists in three places at once. This is the part to be careful with in any redesign.

  • The fixed toolbar above the text, always visible.
  • A floating bar that rises over a selection with the same tools.
  • A block handle that appears on hover at the left of a block: move up, move down, duplicate, remove.
  • A picture in the text gets its own bar: 25 / 33 / 50 / 75 / 100 %, float left, centre, float right, then Opis, Uredi, Zamenjaj, Odstrani. It also resizes by dragging the dot at its corner.

The panel holds seven collapsible sections, in this order.

The picture tool is a full screen modal, used for the main picture, pictures in the text and re-editing anything in the library.

A dark stage holds the picture with a draggable crop box and four round handles. The control bar underneath carries the ratios (Prosto, 16:10, 16:9, 4:3, 3:2, 1:1, 4:5), Zavrti, Cel, the largest width (800, 1200, 1600, 2000), a quality slider and the resulting pixel size. Applying it uploads four files: 800 and 1600 pixels wide, as JPG and WebP.

Flows

What a session actually looks like

  1. Write and publish. New item from the rail or the drawer, fill the three cards, watch the score, Predogled opens the real page in a desktop or phone frame, Objavi. A toast says it will be on the web in about two minutes and the drawer row turns from amber to green.
  2. Fix a published page. Open it from the drawer, edit, Shrani. Changing the URL of a published page asks first, because the old address stops working.
  3. Add a picture. Drop it on the picture card or the library, crop and size it, and it cannot be published until it has a description.
  4. Move an item. Change the collection in the panel. A published item warns that its address changes; its children stay behind without a parent.

Constraints

What cannot move

  • No build step, no framework. One stylesheet and four ES modules loaded directly by index.html, with no external request of any kind, fonts included. A redesign is CSS plus the template strings inside ihg.js.
  • The text the editor produces is filtered on save. Only a fixed set of tags survives, and only these classes: cms-figure, cms-callout, cms-cta, cms-columns, cms-column, cms-table, cms-note (with modifiers), align-left|center|right, c-ink|muted|blue|green|orange|red, hl, lead, small. A new editing affordance must emit one of these, or the class has to be added to the site's stylesheet and the allow-list together.
  • What the editor shows must match the site. The editable area renders the same classes the published page will. Restyle one, restyle the other.
  • Targets stay finger sized. Rail 48px, buttons 40 (34 and 30 for dense desktop toolbars), inputs 40.
  • Slovene, plain words. No English on screen, no internal vocabulary, ever.
  • Phone first. Drawer and panel are overlays below their breakpoints, and everything works with one thumb.
  • Very little motion, and reduced motion is respected. Keep it that way.
  • IHG's CSS is its own. The public site's design audit does not apply here, so borders, radii and shadows are free in a way they are not on the site itself.

Briefs

Where the design is weakest

Ranked by how much fixing them would help. The first four are worth more than the rest together.

The editor between 900 and 1199px

The panel is an overlay at that width, so the form sits alone in a wide column and the screen looks abandoned. Either dock the panel earlier, or let the form use the width.

Seven accordions is not a structure

Publishing, placement, pictures, blocks, SEO, links and stats sit in one flat list of collapsibles. Stages, tabs, or surfacing only what matters at this moment would all beat it.

The SEO block is long and flat

Twelve checklist rows, a ring and eight fields, all at the same volume. Decide what a person looks at first and what can stay hidden until it fails.

The toolbar wraps to three rows

Even at 1440px the text toolbar runs to three rows inside the editor column, and on a phone it fills the screen before a word is written. The same tools need a compact form.

The dashboard says little

Four totals and a bar chart. It could say which page is rising, which is falling, what was published last and what it did.

The media library has no states

No filter, no sense of which pictures are used where, and the same grid is reused as a picker inside the editor without looking like one.

Empty states are one grey line

"Tu še ni ničesar" in the drawer, "Knjižnica je prazna" in the library, "Še ni vsebin" on the dashboard. Each is a chance to teach the product.

The picture tool is plain

A dark stage and a row of small buttons. It is the moment a person feels most in control of the page, and it looks like a utility.

There is no dark theme at all

Worth a deliberate decision: either commit to the paper look and say so, or build the second palette properly. Today it is an omission, not a choice.

Working on it

Files, and how to see your changes

Run npm run admin in website/, then open localhost:4321/admin/. Saving rewrites real content files and rebuilds the site, so the preview is exactly what the public page will be.

Before anything ships: npm run check. It covers the API and the site, not the look.
