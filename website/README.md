# ais-slovenia.si — website

A rebuild of the AIS Slovenia site with the same structure and copy as the
original, optimised for search engines and AI answer engines, and redesigned
around a lighter, quieter, more readable visual language.

The site is generated by a small Node script with **zero dependencies**. There
is no framework, no bundler and no `node_modules`. `npm run build` writes plain
static HTML to `dist/`.

---

## Quick start

```bash
npm run serve    # from the repo root, or from website/
                 # builds, then serves on http://localhost:4321
npm run build    # build into website/dist
npm run check    # build, then run the SEO/GEO audit
```

Node 18 or newer. Nothing to install. If `http://localhost:4321` fails to
open, use `http://127.0.0.1:4321` — some machines resolve `localhost` to IPv6
only. The server binds both `0.0.0.0` and `::` so either URL works.

## Why it was rebuilt

The original site was a client-rendered React SPA. Its HTML response contained
an empty `<div id="root"></div>`, and the app only mounted after a 1.76 MB
JavaScript bundle — a React *development* build including Three.js — had
downloaded and initialised WebGL. Everything below follows from that.

| Issue on the original | Consequence | Status here |
|---|---|---|
| Empty `#root`; content rendered client-side | Crawlers and AI answer engines saw no content | Static HTML, 144–887 words per page |
| Content required WebGL to render at all | Any bot without WebGL got a blank page | No JS required to read any page |
| 1.76 MB JS bundle (React dev build + Three.js) | Slow first paint, poor Core Web Vitals | 11–32 kB of HTML, one CSS file, no JS bundle |
| No `sitemap.xml` (404) | Nothing to submit to Search Console | Generated from the page list |
| No `robots.txt` (404) | No crawl directives, no sitemap pointer | Generated, AI crawlers explicitly allowed |
| No structured data | No rich results, weak entity understanding | JSON-LD `@graph` on every page |
| No Open Graph or Twitter tags | Bare links when shared | Full set + generated OG image |
| No canonical URLs | Duplicate-content risk | Canonical on every indexable page |
| One page, hash anchors only (`#services`) | A single URL had to rank for every topic | 10 indexable URLs |
| `user-scalable=no, maximum-scale=1` | Blocked pinch zoom; accessibility failure | Removed |
| Dead links (`Kariera`, `Pogosta vprašanja`, `Live Chat` → `#`) | Wasted crawl signals, dead ends for users | Real pages; audit fails on `href="#"` |
| Two different contact addresses in the footer | Inconsistent entity data | Single address from `content/site.mjs` |

## Structure

```
website/
├── content/            ← edit here
│   ├── site.mjs        brand, contact details, navigation, SEO defaults
│   └── content.mjs     all page copy: hero, services, process, team, FAQ
├── src/
│   ├── styles.css      the design system
│   ├── layout.mjs      <head>, header, footer, document shell
│   ├── sections.mjs    section components
│   ├── schema.mjs      JSON-LD structured data
│   └── html.mjs        escaping helpers
├── public/             static assets, copied to dist as-is
├── build.mjs           page definitions + generator
├── audit.mjs           SEO/GEO checks
└── vercel.json         deployment config
```

**To change wording, edit `content/content.mjs`.** Pages, navigation, sitemap,
`llms.txt` and structured data all regenerate from it.

## GEO — being cited by AI answer engines

Search optimisation gets a page ranked. Generative engine optimisation gets it
*quoted*. The measures here are specifically for the second:

**Content is in the HTML.** Answer engines fetch a URL and read the response.
Most do not execute JavaScript. The original returned an empty div; every page
here returns its full text.

**Answer-first paragraphs.** Each page opens with a self-contained summary box
(`takeaway()`) that states the answer in two or three sentences without relying
on surrounding context — the format models lift verbatim.

**A real FAQ.** Ten questions with complete, standalone answers, marked up as
`FAQPage`. Question-and-answer text is the single most quotable format there is.
The original linked to a FAQ page that did not exist.

**A connected entity graph.** `Organization`, `WebSite`, `WebPage`, `Service`,
`Person`, `FAQPage`, `HowTo` and `BreadcrumbList` nodes share stable `@id`s, so
engines can resolve what the business is, what it sells and who works there
rather than guessing from prose.

**`llms.txt`.** A plain-text brief at `/llms.txt` restating the facts, agents,
process and FAQ in the cheapest possible form to parse.

**AI crawlers are allowed explicitly.** `robots.txt` names GPTBot,
OAI-SearchBot, ClaudeBot, PerplexityBot, Google-Extended, Applebot-Extended and
others. A site that blocks them cannot be cited by them.

**Consistent facts.** Contact details, agent descriptions and process steps come
from one source, so every page and every schema block agrees. Contradictory
facts across pages make a model less likely to state any of them confidently.

## The automated audit

`npm run audit` checks the built output and **exits non-zero on failure**, so CI
catches regressions. It verifies per page:

- `<title>` present, 20–65 characters
- meta description present, 70–165 characters
- canonical URL present on indexable pages
- exactly one `<h1>`, at least one `<h2>`
- `lang="sl"` on `<html>`
- complete Open Graph set and a Twitter card
- JSON-LD present and parsing as valid JSON, with `Organization` and `WebPage`
- at least 120 words of text in the HTML — this is the check that would have
  caught the original site's empty `#root`
- every `<img>` has `alt`
- viewport does not block zoom
- no dead `href="#"` links
- no empty `#root` (client-side rendering has not crept back in)

And across the site: sitemap, robots and llms.txt exist; every indexable page is
in the sitemap; the 404 is not; no duplicate titles or descriptions; and every
internal link resolves to a page that was actually generated.

CI runs this on every push touching `website/` (`.github/workflows/website.yml`).

## Design

The brief was: lighter, cleaner, smaller type, no overlapping elements,
artistically colourful but still clean, and no colourful buttons.

- **Light.** Paper-white surfaces, ink-dark text. The original was black with
  white text and a full-viewport WebGL canvas behind everything.
- **Small type.** Body is 16px. Display type is capped at `2.85rem` via `clamp()`
  rather than the original's viewport-scaled headlines that ran to hundreds of
  pixels.
- **No overlaying.** Every element is in normal document flow. There are no
  stacked absolutely-positioned layers, no scroll-jacking, no fixed canvas and
  no "ENTER EXPERIENCE" gate. Colour arrives as `background-image` gradients on
  the sections themselves, so it can never sit on top of text.
- **Colour as accent.** Five accents — blue, violet, teal, amber, rose — appear
  in eyebrow rules, card top rules, chip dots, process numerals, stat figures
  and one gradient hairline above the footer.
- **Neutral buttons.** Every button is ink-on-white or white-with-a-border.
  No button uses an accent colour, by design.

Accessibility: pinch zoom restored, a skip link, `aria-current` on the active
nav item, visible focus rings, `prefers-reduced-motion` honoured, and mobile
navigation built on `<details>` so it works without JavaScript.

## The contact form

The form works with no backend: it posts to `mailto:` and opens the visitor's
mail client with the fields filled in.

To submit in the background instead, set an endpoint in `content/site.mjs`:

```js
contact: {
  formEndpoint: 'https://n8n.example.com/webhook/…',
  …
}
```

With an endpoint set, an inline script posts the form as JSON and shows inline
success and error states. Without one, the `mailto:` fallback stands. Either way
the direct address is printed under the form.

## Deployment

`vercel.json` is configured for a static build: `npm run build` → `dist/`, with
`trailingSlash`, long-lived caching for images, and security headers.

Point the Vercel project's root directory at `website/`. There are no
environment variables and no install step.

### After the first deploy

1. Submit `https://ais-slovenia.si/sitemap.xml` in Google Search Console and
   Bing Webmaster Tools. Neither could previously be given a sitemap.
2. Check `/robots.txt` and `/llms.txt` resolve.
3. Validate a page in Google's Rich Results Test — the FAQ and HowTo blocks are
   eligible for rich results.
4. Keep the LUCY chat widget: it was on the original site but is not included
   here, since it loaded a third-party markdown parser and a 363 kB image on
   every page. Re-add it as a deferred script if you want it back.

## Adding a page

1. Write the copy in `content/content.mjs`.
2. Add a function in `build.mjs` returning `{ path, title, description,
   breadcrumbs, schema, body }`.
3. Register it in `collectPages()`.
4. Add it to `site.nav` in `content/site.mjs` if it belongs in the header.

Sitemap, `llms.txt`, internal-link checking and the audit pick it up
automatically.
